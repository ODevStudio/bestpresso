# Translations (i18n)

## Purpose

Let Bestpresso show its interface in more than one language without adding a runtime dependency. English stays the source language and its wording is unchanged; German is the first translation.

## Product principles

- English is the source of truth. `src/i18n/en/*.ts` holds today's wording verbatim, so English users see no change.
- No i18n framework. A typed catalog plus `Intl` covers everything Bestpresso needs (messages, placeholders, one/other plurals, numbers, dates).
- A missing or extra translation is a type error, not a runtime surprise.
- Only Bestpresso's own text is translated. Profile names, descriptions and stage names come from the profile JSON and stay as their author wrote them; messages passed through from Decaid stay as Decaid sends them.
- Stored data never changes language. Values written to Decaid, the history cache or profile JSON remain English identifiers; translation happens when text is displayed.

## Choosing the language

`Settings → App experience → Display → Language` offers:

| Option | Behaviour |
|---|---|
| Follow device (default) | First entry of `navigator.languages` that Bestpresso supports; otherwise English |
| English | Always English |
| Deutsch | Always German |

The choice is stored with the other Bestpresso preferences (`language` in `bestpresso.preferences.v1`) and applies immediately without a reload. `<html lang>` follows the active language.

Number and date formats follow the active language and keep the device region when it matches (`de-CH` keeps the decimal point, `de-DE` uses a decimal comma).

## Code layout

```
src/i18n/
  index.ts        t(), plural(), formatDecimal(), formatNumber(), parseLocalizedNumber(), dateFormatter(), useLanguage()
  types.ts        Translation<Source>: every key of the English area, nothing else
  en/<area>.ts    English source catalog, one file per feature area (common, shell, brew, insights, library, builder, settings)
  de/<area>.ts    German catalog, same keys
```

Keys are semantic and prefixed with their area, for example `brew.liveScreen.stop` or `settings.power.schedule.title`. The same English word can therefore translate differently in different places.

## Writing UI text

```ts
import { t, plural, formatDecimal } from '../../i18n/index.ts'

t('brew.liveScreen.stop')                        // "Stop" / "Stopp"
t('shell.brewStage.stageNumber', { n: 3 })       // "Stage 3" / "Phase 3"; placeholders are typed
plural('settings.power.schedule.daysCount', n)   // { one: '{count} day', other: '{count} days' }
formatDecimal(weight, 1)                         // "36.5" / "36,5" — same rounding as toFixed
```

Rules:

1. Add the English text to `en/<area>.ts` and the translation to `de/<area>.ts`. `tsc` fails until both exist.
2. Keep whole sentences in one message and use placeholders; word order differs between languages.
3. Do not call `t()` at module level. Module constants are evaluated before the language is known and never update. Use a function, a getter, or store the key and translate while rendering.
4. Never compare against translated text. Compare ids (`metric.id === 'target'`) and translate only for display.
5. Use `formatDecimal`/`formatNumber` for numbers that are shown, and keep `toFixed` for values that are sent to Decaid, stored, or parsed again.

## Adding a language

1. Copy `src/i18n/de/` to `src/i18n/<code>/`, rename the exports and translate the values.
2. Add the code to `Language`, `LANGUAGES` and the catalog map in `src/i18n/index.ts`, plus `common.language.<code>`.
3. Accept the code in `normalizeBestpressoPreferences`.

The Streamline/DE1 translation table (`src/ui/de1 gui translation - Sheet1.csv` in allofmeng/streamline_project) is a useful terminology reference for existing DE1 languages.

## Testing

- `npm test` includes `test/i18n.test.ts`: identical key sets per area, identical placeholders, no empty translations, area prefixes, language resolution and number formatting.
- Pseudo locale: open Bestpresso with `?i18n-pseudo` to wrap every translated string in `⟦…⟧`, accent its vowels and make it about 35 % longer. Text without brackets was not extracted; clipped brackets show layout that cannot take longer translations.
- Check German at 1280 × 800, the common tablet size.
